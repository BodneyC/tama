# Roadmap

Work through milestones **in order**. Each milestone ends with the full check passing
(`/check`) and a commit (or several). Tick boxes as you go. Don't start UI work before the
domain milestone is green — the domain is the foundation.

## M5 — Animation & art

Sprites become colour pixel art drawn with block characters (`█ ▀ ▄ ░ ▒ ▓`); see
[ADR 0003](adr/0003-pixel-art-sprites.md), [ADR 0004](adr/0004-species-palettes-and-themeable-ui.md)
and the `/add-sprite` command for the format.

- [x] Pixel sprite format: TOML pixel grid + palette (`.` transparent, optional `shade`),
      `fps`/`loop`; Pydantic validation (palette coverage, even height, ≤ 32×20 px, equal
      frame sizes)
- [x] Pure renderer: pixel pairs → `▀`/`▄`/`█`/space with fg/bg colours, shaded entries →
      `░`/`▒`/`▓`; unit-tested cell by cell; frames cached as Textual `Content`
- [x] Monochrome fallback under `NO_COLOR` (light pixels drawn, dark pixels become gaps)
- [x] Replace the M4 ASCII `.txt` sprites and loader with pixel-art idle frames for every
      stage; `test_sprites.py` validates every sprite file and that each stage has an idle
- [x] `test_sprites.py` requires every (stage, animation) from SPEC §5.2, shared canvases,
      loop/one-shot flags, and that the committed art matches the generator
- [x] `PetView` widget: looped + one-shot playback at each file's `fps`, wandering, blink
- [x] Full pixel-art set (generated by `tools/sprites/`): all stages × animations
      in SPEC §5.2 with one palette, plus distinct "good" (crowned) and "scruffy" adults and elders
- [x] Hatch and evolve sequences; Zzz/sick/poop overlays as small pixel sprites
- [x] Lights-off dimming of the pixel sprite (tint)
- [x] `--reduced-motion`; config `theme` applied; dark & light snapshots for every stage
- [x] Per-species `base.toml` palettes with dark/light colours; animation files only override
      (ADR 0004)
- [x] Themeable UI colours: `assets/ui.toml` defaults (incl. Textual theme references) as
      `$tama-*` CSS variables, overridable per species in `[ui]`
- [x] Monochrome follows the mode (light-on-dark, line art on light); every sprite must draw
      something in every look
- [x] Generators split into `tools/sprites/` (shared kit + one module per species)

**Accept:** Snapshot tests for each life stage's idle key frame in colour, on a dark and a light
theme, plus one under `NO_COLOR`, each reviewed as a rendered image; manual check at
`--speed 600`.

- [x] Snapshots: each species' stages on dark and light themes, reviewed as images

## M6 — Remaining screens & polish

- [x] `AwaySummaryScreen` (currently a toast), `MemorialScreen`, `ErrorScreen` (currently the app
      exits with a message); animate `FeedMenu` and `MiniGameScreen` (basic versions from M4)
- [x] Attention calls with blinking indicator + optional bell
- [x] Balancing pass: play at `--speed 60` for a full life; adjust `Balance` only
      (known: an untreated sick child dies in ~2.5 h — sickness may need to be gentler).
      Done headlessly with `tools/balance.py` (simulated players who sleep 23:00-07:00):
      sickness and neglect now take ~13-17 h to kill, hunger/happiness drift slower and base
      sickness is 1%/h. Diligent and casual players reach old age 30/30, a 2-hourly player
      29/30 (scruffy). A whole day away is still fatal (open question for the design).
- [x] Logging to file; no stray terminal output (landed in M4)

**Accept:** A complete life can be played start to finish; every screen has a snapshot test.

## M6.5 — More mini-games

Two board games against the pet, chosen from a game select dialog (SPEC §3.1, ADR 0006).

- [ ] Domain: `tama.domain.minigames` package with `GameKind` and `GameResult` (win/draw/loss);
      move Left or Right there from `domain/minigame.py`
- [ ] Domain: `apply_game_outcome(pet, result, ctx)` and `Played(result)` with the draw effect
      (happiness +10, energy −10); `Balance.play_draw_happiness` and per-stage opponent
      mistake chances
- [ ] Domain: Four in a Row (7×6): drop, full columns, win in all four directions (winning
      cells reported), draw on a full board — test-first
- [ ] Domain: Tic-Tac-Toe (3×3): place, occupied cells, all eight lines, draw — test-first
- [ ] Domain: `opponent.py`: wins, blocks, avoids handing Four in a Row wins, positional
      preference, mistakes; property tests (random legal games always finish with exactly one
      result; the pet never makes an illegal move; with no mistakes it never misses a win or a
      block)
- [ ] Services: `GameSession.pet_move(game)` and `finish_game(result)` using the session RNG
- [ ] UI colours `piece-player` and `piece-pet` in `assets/ui.toml` (dark/light, theme refs
      allowed) and the `/add-sprite` UI colour list; species may override them
- [ ] UI: `GameSelectScreen` (`↑`/`↓` + `Enter`, `1`–`3`, `Esc`; remembers the last game this
      session); `p` opens it after the play refusals; Help text updated
- [ ] UI: `FourInARowScreen` (column marker, `←`/`→` wrap and skip full columns, `↓`/`Enter`
      drop, falling pieces, pet "thinking", winning four highlighted, `●`/`○` in monochrome)
- [ ] UI: `TicTacToeScreen` (cursor, `Enter`/`Space`, keypad-layout `1`–`9`, winning line
      highlighted)
- [ ] Reduced motion: no thinking pause or falling pieces
- [ ] Snapshots: game select; each board game mid-game and finished; monochrome and light
      variants of Four in a Row; all fit 60×20
- [ ] Balance check: extend `tools/balance.py` (or a sibling) to play many games with a simple
      scripted player and confirm young pets are easy and adults challenging

**Accept:** from the main screen a player can pick each of the three games, play it to a win,
draw or loss with the keyboard, and see the right effect on the pet; the board games are
readable in colour, light theme and monochrome at 60×20.

## M6.6 — Several tamas

Keep up to nine pets, pick which to play, and see them all from the shell (SPEC §6.1, ADR 0007).

- [ ] Persistence: `PetRoster` over `pets/` — list pet files, create `<slug>-<id>.json` for a
      new pet, `last.json` (fallback: most recently updated), archive to `pets/archive/`;
      tests with `tmp_path` incl. unreadable files, a missing/corrupt `last.json`, and names
      that need slugging (spaces, emoji, path separators)
- [ ] Persistence: legacy migration — an existing `save.json` (+ `.bak`) moves into `pets/` and
      becomes last played; idempotent; an interrupted move never loses a file
- [ ] Persistence: per-pet lock (`.lock` with pid; stale locks taken over; released on exit and
      on SIGTERM/SIGHUP)
- [ ] Services: `PetSummary` for every pet as of now (read-only capped catch-up, never saves);
      unique-name check for living pets; 9-pet limit; startup time with 9 pets measured
- [ ] CLI: `--pet NAME` (case-insensitive, unique prefix, living before dead; ambiguous or
      unknown → usage error listing the pets); `--new` adds a pet (refused at 9);
      `--species` with `--pet` errors on a different species; `--save-path` still plays one file
- [ ] CLI: `--status` (and `tama status` as an alias): one line per pet, last played first with
      `*`; `--status --pet NAME` for one; exit codes 0/1/2 as SPEC §8
- [ ] UI: `PetSelectScreen` — small idle sprites, name, species, stage, age, `⚠` reasons,
      gravestones for dead pets, "can't be read" rows; `↑`/`↓`, `1`–`9`, `Enter`, `n`, `a`
      (confirm), `Esc`/`q`; shown at launch when there are several pets
- [ ] UI: `t` on the main screen saves and switches pets; UI colours follow the open pet;
      the name prompt rejects a living pet's name; the memorial's "new egg" adds a pet
- [ ] UI: header `⚠ +N` for other pets needing care (re-checked every minute, read-only; no
      bell); Help text and footer updated
- [ ] Unreadable pets open the per-file `ErrorScreen` without affecting the others
- [ ] Snapshots: pet select (several pets incl. one dead, one needing care, one unreadable;
      light theme; monochrome); header with `⚠ +N`; all fit 60×20
- [ ] Docs: README/`--help` explain several pets and the changed `--new`

**Accept:** with three pets saved (one dead), `tama` offers all three, plays the chosen one,
switches to another with `t`, and `tama --status` prints each pet's state as of now without
changing any save; an old single `save.json` is picked up automatically.
