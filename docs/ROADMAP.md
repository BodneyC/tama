# Roadmap

Work through milestones **in order**. Each milestone ends with the full check passing
(`/check`) and a commit (or several). Tick boxes as you go. Don't start UI work before the
domain milestone is green — the domain is the foundation.

## M5 — Animation & art

Sprites become colour pixel art drawn with block characters (`█ ▀ ▄ ░ ▒ ▓`); see
[ADR 0003](adr/0003-pixel-art-sprites.md) and the `/add-sprite` command for the format.

- [x] Pixel sprite format: TOML pixel grid + palette (`.` transparent, optional `shade`),
      `fps`/`loop`; Pydantic validation (palette coverage, even height, ≤ 32×20 px, equal
      frame sizes)
- [x] Pure renderer: pixel pairs → `▀`/`▄`/`█`/space with fg/bg colours, shaded entries →
      `░`/`▒`/`▓`; unit-tested cell by cell; frames cached as Textual `Content`
- [x] Monochrome fallback under `NO_COLOR` (light pixels drawn, dark pixels become gaps)
- [x] Replace the M4 ASCII `.txt` sprites and loader with pixel-art idle frames for every
      stage; `test_sprites.py` validates every sprite file and that each stage has an idle
- [x] `test_sprites.py` requires every (stage, animation) from SPEC §5.2, shared canvases,
      loop/one-shot flags, and that the committed art matches the generator
- [x] `PetView` widget: looped + one-shot playback at each file's `fps`, wandering, blink
- [x] Full pixel-art set (generated by `tools/generate_sprites.py`): all stages × animations
      in SPEC §5.2 with one palette, plus distinct "good" (crowned) and "scruffy" adults and elders
- [x] Hatch and evolve sequences; Zzz/sick/poop overlays as small pixel sprites
- [x] Lights-off dimming of the pixel sprite (tint)
- [x] `--reduced-motion`; config `theme` applied; dark & light snapshots for every stage

**Accept:** Snapshot tests for each life stage's idle key frame in colour, on a dark and a light
theme, plus one under `NO_COLOR`, each reviewed as a rendered image; manual check at
`--speed 600`.
